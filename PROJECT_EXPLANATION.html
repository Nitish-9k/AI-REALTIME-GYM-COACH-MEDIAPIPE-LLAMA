AI Real-time Gym Coach — Interview Explanation

Repository: Nitish-9k/AI-REALTIME-GYM-COACH-MEDIAPIPE-LLAMA

1. Project in one minute

This is a Streamlit web application that acts as a real-time personal gym coach. It receives webcam frames through WebRTC, uses OpenCV to prepare and draw on the frames, and uses MediaPipe Pose Landmarker to detect body landmarks. Exercise-specific detector classes calculate angles, count repetitions, and evaluate form for squats, push-ups, lunges, biceps curls, and shoulder presses. The metrics are shown in the UI and sent to LLaMA through Groq; gTTS converts the generated feedback into voice audio. Workout progress is saved in SQLite.

Interview summary: WebRTC transports video, OpenCV processes and annotates frames, MediaPipe detects landmarks, detector classes interpret movement, LLaMA generates coaching language, gTTS speaks it, and SQLite stores workout history.

2. Runtime flow

Login with username
  -> Select exercise, sets, and repetitions
  -> Start WebRTC webcam stream
  -> VideoProcessorClass.recv(frame)
  -> OpenCV flip/color conversion
  -> MediaPipe pose landmark detection
  -> Selected exercise detector.process(landmarks)
  -> Angles, form status, and repetition count
  -> Streamlit session state and dashboard
  -> LLaMA feedback -> gTTS audio -> browser playback
  -> Completed sets stored in SQLite

3. Classes created in the project

3.1 BaseExercise — core/base_exercise.py

Purpose: Abstract base class for all exercise detectors. It centralizes shared geometry and defines the interface every exercise must follow.

  • __init__(): initializes reps = 0 and stage = None.
  • calculate_angle(a, b, c): calculates the angle at point b using two vectors, a dot product, vector magnitudes, and acos. It protects against zero-length vectors and clamps the cosine value between -1 and 1.
  • get_points(landmarks, idx): converts a MediaPipe landmark into its normalized (x, y) coordinate pair.
  • process(landmarks): abstract method. Each child detector implements exercise-specific analysis.
  • reset(): abstract method. Each child resets its repetition state.

Design concept: inheritance avoids duplicating angle logic while polymorphism allows the video processor to call the same process() method for different exercises.

3.2 SquatsDetector — detectors/squats.py

Purpose: Counts squats and evaluates knee angle, back angle, and squat depth.

  • Calculates left and right hip-knee-ankle angles.
  • Chooses the side with better knee landmark visibility.
  • Uses knee angle below 100° as the down position and at least 160° as the up position.
  • Counts one repetition only when the state changes from down to up.
  • Calculates back angle using shoulder, hip, and knee.
  • Returns reps, knee_angle, back_angle, and depth_status.

3.3 PushUpDetector — detectors/pushups.py

Purpose: Counts push-ups and checks body alignment and hip position.

  • Selects the side with the more visible elbow.
  • Calculates shoulder-elbow-wrist angle for arm movement.
  • Uses elbow angle below 90° for down and above 160° for up.
  • Calculates shoulder-hip-ankle body angle and classifies it as STRAIGHT, SLIGHT BEND, or POOR FORM.
  • Compares actual hip height with the expected midpoint between shoulder and ankle to detect LEVEL, sagging, or raised hips.

3.4 LungesDetector — detectors/lunges.py

Purpose: Counts lunges and evaluates the front knee, torso angle, and balance.

  • Calculates both knee angles and treats the smaller angle as the front knee.
  • Uses below 100° as the down position and above 160° as the up position.
  • Calculates torso angle using shoulder, hip, and knee.
  • Measures the horizontal shoulder-to-hip offset to classify the user as BALANCED or OFF BALANCE.

3.5 BicepsCurlDetector — detectors/biceps.py

Purpose: Counts dumbbell curls and detects elbow drift and torso swinging.

  • Selects the arm with greater elbow visibility.
  • Uses elbow angle below 50° as the curled-up position and above 160° as the lowered position.
  • Counts a repetition after an up-to-down transition.
  • Compares elbow and shoulder x-coordinates to detect stable or drifting elbows.
  • Calculates torso angle from shoulder and hip midpoints; an angle above the swing threshold indicates swinging.
  • _safe_angle(dx, dy) safely calculates torso angle with atan2.

3.6 ShoulderPressDetector — detectors/shoulder_press.py

Purpose: Counts shoulder presses and evaluates arm extension and back arch.

  • Selects the arm with greater elbow visibility.
  • Uses elbow angle above 160° as up/full extension and below 90° as down.
  • Classifies extension as full, nearly extended, pressing, or start position.
  • Calculates the shoulder-hip-knee back angle.
  • Classifies back posture as neutral, slight arch, or excessive arch.

3.7 VideoProcessorClass — services/vision/exercise_viseo_processor.py

Purpose: Main real-time video-processing class. It connects WebRTC, OpenCV, MediaPipe, and the exercise detectors.

  • Inherits from VideoProcessorBase, allowing streamlit-webrtc to call recv() for every frame.
  • __init__() loads pose_landmarker_full.task, configures MediaPipe video mode and confidence thresholds, and creates one detector object for each supported exercise.
  • recv(frame) converts the incoming frame to a NumPy array, flips it, changes BGR to RGB, runs MediaPipe, calls the selected detector, draws overlays, stores metrics, and returns an av.VideoFrame.
  • _draw_skeleton() draws visible landmarks and configured pose connections with OpenCV.
  • _draw_no_pose_warnings() displays a warning when no pose is found.
  • _draw_overlays() dispatches to exercise-specific overlay methods.
  • set_latest_metrics() and get_latest_metrics() safely share metrics between the video thread and Streamlit.
  • set_exercise() and get_exercise() safely manage the selected exercise.
Concurrency: The class uses threading.Lock because WebRTC processing and Streamlit UI updates can run in different execution contexts.

3.8 LLMCOACH — services/coaching/LLM.py

Purpose: Wraps the Groq client and turns workout events into short natural-language coaching responses.

  • __init__(groq_client) stores the client, prompt, and response history.
  • give_feedback(event, issue, username) builds a prompt containing the event, user name, and form issue.
  • It sends a system prompt plus recent history to the llama-3.3-70b-versatile model with temperature 0.4.
  • Returns the cleaned assistant response and keeps recent assistant responses for context.

3.9 TextToSpeech — services/coaching/tts.py

Purpose: Converts the LLM text into browser-playable MP3 bytes.

  • speech(text, lang="en") strips empty input, creates a BytesIO buffer, calls gTTS, and returns the audio bytes.

3.10 voice_pipeline — services/coaching/voice_pipeline.py

Purpose: Orchestrates issue detection, LLM feedback, text-to-speech, and audio timing.

  • _find_form_issue(exercise, metrics) translates structured detector metrics into a human-readable form issue.
  • process_event(event, exercise, metrics, username) handles major events immediately and rate-limits ongoing corrections to once every five seconds.
  • It calls LLMCOACH.give_feedback(), then TextToSpeech.speech(), and returns audio plus text.
  • autoplay_audio(audio_bytes) hides the normal audio widget and asks Streamlit to autoplay the generated MP3.

The class name is lowercase in the current repository; Python convention would normally use VoicePipeline.

5. Technologies

  • Streamlit: Python-based UI and session state.
  • WebRTC: Real-time browser webcam transport.
  • OpenCV: frame conversion, flipping, drawing, and overlays.
  • MediaPipe: 33-point human pose landmark detection.
  • Groq + LLaMA: short contextual coaching language.
  • gTTS: text-to-speech audio generation.
  • SQLite: local user and workout persistence.

6. How to run

git clone https://github.com/Nitish-9k/AI-REALTIME-GYM-COACH-MEDIAPIPE-LLAMA.git
cd AI-REALTIME-GYM-COACH-MEDIAPIPE-LLAMA
pip install -r requirements.txt
export GROQ_API_KEY="your_groq_api_key_here"
streamlit run main.py

Use a browser with webcam permission. Linux deployments may also need the packages in packages.txt.

7. Limitations and improvement points

  • Pose thresholds are fixed and may need calibration for different users, camera angles, and body proportions.
  • Only the first detected pose is used.
  • Ongoing feedback can generate frequent API/TTS calls; production code could batch or debounce events more aggressively.
  • SQLite is suitable for a small deployment but a server database would be better for multiple users.
  • The notebook in JupyterNotebook/EDA&DATAPREP.ipynb analyzes resume/job data and is separate from the gym-coach runtime.

8. Final interview answer

“My project is a real-time AI gym coach. The browser sends webcam video through WebRTC. OpenCV prepares each frame, and MediaPipe detects body landmarks. I created a common BaseExercise class for angle calculation and then implemented separate detectors for squats, push-ups, lunges, biceps curls, and shoulder presses. Each detector uses visibility checks, joint-angle thresholds, and a down/up state machine to count valid repetitions and identify form problems. The metrics are displayed in Streamlit and passed to a voice pipeline. LLaMA through Groq converts the detected event into a concise coaching sentence, gTTS converts it to speech, and the audio plays in the browser. Completed workout sets are stored in SQLite and displayed as history.”
